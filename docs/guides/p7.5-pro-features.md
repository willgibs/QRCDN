## Why this phase exists

Everything the Pro pricing page sells must exist before marketing screenshots it
(road-to-launch rule: no vaporware rows). After P7, three D14 rows remained
unbuilt: vanity slugs, access controls, bulk generation. `expires_at` and
`password_hash` had existed as dormant schema since P3 — zero migrations needed.

## Scope (as shipped)

1. **Worker enforcement** — `KvSlugRecord` gained optional `expiresAt` (ISO) and
   `passwordProtected` (derived boolean — **the hash never reaches KV**).
   Decision order, symmetric across KV-hit and REST branches:

   | state | decision |
   |---|---|
   | paused / non-active | unclaimed → `/u/{slug}` |
   | expired (request-time compare) | unclaimed → `/u/{slug}` |
   | password-protected | password → `/p/{slug}` |
   | otherwise | 302 destination |

   Expiry outranks password deliberately: a dead code reads as gone, never
   invites guessing. Request-time comparison means KV entries expire on schedule
   with no rewrite. Absent fields reproduce pre-P7.5 behavior exactly (the
   `codeId` additive-rollout property) — old KV entries self-heal via TTL.
   Password-walled scans still ingest (the scan happened).
2. **Passwords** (`apps/web/lib/passwords.ts`) — promisified async
   `node:crypto.scrypt` (never `scryptSync`: it blocks the event loop under
   Fluid compute), N=2¹⁵/r=8/p=1/len 64, **explicit `maxmem: 64MiB`** (the
   parameter set needs exactly Node's 32MiB default — omitting the bump works in
   dev and intermittently throws in prod). Self-describing format
   `scrypt$N$r$p$saltB64$hashB64`: verify reads params from the stored string,
   so future cost bumps never rehash. Params sit below OWASP's interactive
   baseline deliberately: billed serverless CPU, no rate limiting until P10, and
   the threat model is a per-code access gate, not an account credential —
   revisit (bump N) when P10's rate limiting lands.
3. **`/p/{slug}` unlock page** — dynamic, admin-client lookup (anon has no RLS
   path). Not-found/paused/expired → `/u` (neutral); **unprotected → straight to
   the destination** (a stale-KV window must never break "your code never
   dies"); else the unlock form → `verifyCodeAccess` server action (TOCTOU
   re-fetch, generic failures, constant ~150ms delay on wrong password).
   **Posture:** `/p` confirming "exists + protected" is inherent to the feature
   and no worse than holding the printed code. Per-IP rate limiting is
   explicitly absent until P10 (Turnstile/WAF — the same Vercel-Pro constraint
   as D11's amendment); scrypt cost + the delay is the documented interim.
4. **The KV-wipe fix** — retarget/pause previously built their KV records from
   3 columns; once access flags existed they would have silently wiped them on
   every write. One shared `toKvRecord()` mapper now feeds every KV write path;
   regression tests pin full-record writes.
5. **Safe surfacing** — `DynamicCodeSummary` carries derived
   `expiresAt`/`passwordProtected`; the raw hash never crosses the codes-core
   mapping boundary (studio page switched off its duplicate raw query so the
   stripping exists in exactly one place). API `ApiCode` exposes both fields;
   PATCH accepts `expiresAt` (null clears). **Password is UI-only in P7.5** —
   plaintext passwords in API request bodies need their own logging/transport
   hygiene review; deferred with reasoning, not forgotten.
6. **Vanity slugs** — `validateVanitySlug`: trim → uppercase → the **narrow**
   `SLUG_CHARSET` (print-confusability applies to human picks too: `SALE2026`
   is rejected for `0`+`L`, and the UI helper text lists the allowed set) →
   `RESERVED_SLUGS` blocklist (D12: trust/UX safeguard — apex-vs-www means no
   literal route collision today; blocked anyway). Vanity insert = single
   attempt, `23505` → `slug_taken` (no silent retry); auto-slug path
   byte-identical to before. Pro-gated in core (`vanitySlugs`), studio
   ("Customize link", Pro-locked), and API (`slug` on POST: 403 gate/422 taken).
7. **Bulk creation** — `createDynamicCodesBulkCore`: batch gates (empty /
   >50 / plan `bulk` / single `existing + n > limit` check), then sequential
   **partial-success** processing — one bad line reports as that line's failure
   while the rest mint (the paste-a-print-batch reality; sequential avoids a
   50-way pool burst). No KV write on create (read-through covers first scan).
   Studio dialog: one destination per line, optional `name | url`, results rows
   + CSV export via the existing `downloadBlob`. UI-only (API bulk deferred).

Out of scope: API bulk, API password, burst rate limiting (all P10-or-later,
each with its reason recorded above).
