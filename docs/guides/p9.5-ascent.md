## Mission

Board round 1 on the P9 storefront: directionally great, far from Resend-level. This
phase closes that gap across every marketing surface, fixes two real auth bugs, and
builds the trust layer of an established product: feature pages, docs ascent,
changelog, status, blog, help — plus the open-source pack. **Pacing mandate: scope
never dilutes per-section polish; chunks ship when they meet the bar.**

## Board decisions locked (2026-07-30)

- **Open source: approved. MIT.** README-as-marketing, SECURITY.md (hello@qrcdn.com),
  minimal CONTRIBUTING ("built in the open, developed as a cathedral"), Built-in-the-

  *if we ever disappear, the path off is public.*

  platforms), named-vendor /compare pages post-launch with sourced claims.
- **Blog byline: Will Gibson, company-forward voice** — QRCDN is the entity; no
  solo-founder/build-in-public framing anywhere.
- **Two-register copy principle:** plain-language benefit headline (owners/execs) +
  mono technical proof-strip (developers), every section, devtool-esque theme.
- Cadence: artifact gate (board picks) → chunked builds, each board-reviewed on
  production before the next begins.

## Standing constraints

- Marketing routes stay `○ (Static)` — audited every unit.
- Entitlement numbers render only via `lib/entitlements.ts`/`lib/pricing.ts` imports.
- Print-truth rule: instrument-bearing QR surfaces stage on their own paper mat.
- Motion: tokens only; max one auto-advancing element per viewport; reduced-motion
  paths mandatory.
- Honesty: no fake metrics/logos/testimonials; blog/help/changelog describe only real
  work and behavior; comparison rows sourceable to our docs or category-common facts.
- **`supabase config push` is banned** (D16): the committed `[auth]` block is
  stale/local (`site_url=localhost`); the dashboard is authoritative. No dry-run
  exists — a push would clobber production auth.

### T0 — Auth fixes (P0, first)
Diagnosis (read-only): dashboard email-template shape · SMTP settings (D9 says Resend
from day one; verify) · auth logs for the failed sign-up (rapid `otp_expired` pairs =
scanner fingerprint; GoTrue can't distinguish expired from consumed) · redirect
allow-list. Note: `signInWithOtp` creates users at SEND time — the reported address
likely exists half-created; handle deliberately.
Fix regardless: template → `{{ .RedirectTo }}?token_hash={{ .TokenHash }}&type=email`
(browser-independent; `email` not deprecated `magiclink`) · `/auth/confirm` becomes
page + `"use server"` `confirmSignInAction` + auto-submit island — a bare GET renders
the interstitial and consumes NOTHING; the visible "Confirm sign-in" button is the
no-JS fallback; `force-dynamic` with the safety comment · `/auth/callback` untouched ·
error flags `auth_error=link_invalid|oauth_failed` with distinct copy (CEO-final) ·
sent-state resend with countdown · e2e: money-path evolves (type=email + interstitial
assertion), new `auth-scanner-safety.spec.ts` (request.get must not consume; same
token then completes via page flow) · D16 entry + config.toml header comment.
Session-aware chrome: `hooks/use-session-affordance.ts` (signed-out first paint,
cookie-presence regex fast-path, `getClaims()` truth, `onAuthStateChange`) +
`NavAuthSlot` replacing both CTAs with "Open studio →" when authed (desktop + mobile).
`/login`: authed → `redirect("/studio")`; dual-mode copy (no tabs — backend is
identical either way); metadata retitle; noindex stays.
